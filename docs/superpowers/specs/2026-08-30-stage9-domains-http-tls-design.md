# Stage 9 — Domains, HTTP Endpoints and TLS

## Status

Approved design direction: Traefik remains the owner of ACME issuance, renewal, and private certificate keys. Resource Portal owns desired routing/TLS state, Domain lifecycle, assignment, validation, and observed TLS metadata.

## Context

Stage 9 is already mostly implemented on `main` after Stage 8. Existing code provides:

- `HttpEndpoint` attached to `SingleApp`,
- protocol modes `HTTP`, `HTTPS`, `HTTP_AND_HTTPS`, and `HTTP_REDIRECT_TO_HTTPS`,
- tenant-owned `Domain` and `CustomRootDomain`,
- managed/custom hostname generation,
- DNS TXT ownership verification for custom root domains,
- Domain ↔ HttpEndpoint assignment and delete protection,
- Traefik labels for host routing, container ports, TLS routers, and HTTP→HTTPS redirects,
- TLS metadata fields including enablement, certificate status, and expiry.

The remaining Stage 9 gaps are the operational TLS lifecycle and immediate routing reconciliation:

- TLS enablement is not yet fully derived/enforced from protocol mode,
- HTTPS routers do not yet select an ACME certificate resolver,
- Resource Portal does not reconcile observed certificate status/expiry,
- automatic renewal is not represented in observed RP state,
- deleting or detaching an endpoint relies on a later stack deployment to remove live routing.

## Goals

Complete Stage 9 without introducing a second certificate authority or moving private certificate keys into Resource Portal.

The completed stage must provide:

1. deterministic TLS requirement semantics from `HttpEndpoint.protocolMode`,
2. Traefik ACME resolver configuration for TLS routers,
3. observed certificate lifecycle metadata in Resource Portal,
4. renewal observation/reconciliation,
5. prompt route removal when an endpoint or Domain assignment is removed,
6. tests that prove routing/TLS behavior and protect existing tenant isolation and deployment behavior.

## Non-goals

This stage does not add:

- manual certificate/key upload,
- a Resource Portal ACME client or independent certificate issuer,
- storage of private certificate keys in the RP database,
- automated DNS mutation for external custom domains,
- path-based routing,
- sharing one FQDN between multiple endpoints,
- a generic Operations/Jobs subsystem; that remains Stage 16.

## Architecture

### Responsibility boundary

Traefik owns:

- ACME protocol execution,
- certificate issuance,
- certificate renewal,
- certificate/key persistence in its ACME storage,
- selection and presentation of certificates at ingress.

Resource Portal owns:

- whether an endpoint requires TLS,
- generated Traefik desired configuration,
- Domain/HttpEndpoint lifecycle and tenant isolation,
- reporting observed certificate status and expiry,
- reconciling ingress when desired Domain/HttpEndpoint routing changes.

This keeps certificate private keys out of RP while making the Stage 9 API state meaningful.

## TLS semantics

`HttpEndpoint.protocolMode` is the source of truth for whether TLS is required.

| Protocol mode | HTTP router | HTTPS router | TLS required |
|---|---|---|---|
| `HTTP` | yes | no | no |
| `HTTPS` | no | yes | yes |
| `HTTP_AND_HTTPS` | yes | yes | yes |
| `HTTP_REDIRECT_TO_HTTPS` | redirect router | yes | yes |

The renderer must not rely on an independently editable `tlsEnabled` flag that can contradict `protocolMode`.

Where the existing persistence model contains a TLS-enabled field, Resource Portal should maintain it as a derived/normalized representation of protocol mode rather than an independent source of truth.

For domains assigned only to HTTP endpoints, certificate state should remain `Pending`/not-required according to the existing API representation and must not trigger ACME configuration.

## Traefik ACME integration

A configurable certificate resolver name will be added to Resource Portal configuration, for example:

`TRAEFIK_CERT_RESOLVER=letsencrypt`

For every TLS router generated by Resource Portal, the stack renderer will emit:

`traefik.http.routers.<router>.tls=true`

and, when the configured resolver is non-empty:

`traefik.http.routers.<router>.tls.certresolver=<resolver>`

The same resolver applies to `HTTPS`, the HTTPS half of `HTTP_AND_HTTPS`, and the HTTPS router of `HTTP_REDIRECT_TO_HTTPS`.

HTTP-only routers must not receive TLS or certresolver labels.

Configuration validation should reject invalid resolver names rather than silently producing malformed Traefik labels.

The RP application stack does not need direct access to ACME private keys.

## Certificate observed state

Resource Portal will introduce a focused Traefik certificate observation adapter/service. Its responsibility is to obtain safe metadata needed by RP and map it to existing Domain fields.

The adapter must expose only metadata necessary for Stage 9, such as:

- hostnames/SANs associated with an active certificate,
- certificate expiry time,
- whether a certificate is currently available,
- observation errors.

The implementation may consume Traefik's supported runtime/API representation available in the deployed environment, but it must not copy certificate private keys into RP or persist plaintext private material.

### Mapping to Domain certificate status

For a Domain currently requiring TLS:

- `Pending` — route requires TLS but no active certificate has yet been observed,
- `Issuing` — RP has configured ACME and the certificate is not yet active while issuance is expected/in progress,
- `Active` — a certificate covering the hostname is observed and not expired,
- `Error` — observation or issuance state indicates a persistent/problem condition that can be represented safely.

`certificateExpiresAt` is populated only from observed certificate metadata. It is not predicted from issuance time.

For a Domain no longer used by any TLS endpoint, RP should normalize TLS observation state so stale `Active` metadata is not presented as proof that TLS is currently required by desired state.

## Certificate reconciliation

A small reconciliation service will periodically inspect Domains assigned to TLS-requiring endpoints and refresh observed certificate metadata.

Properties:

- interval is configuration-driven,
- reconciliation is idempotent,
- failures for one Domain do not stop reconciliation for other Domains,
- only metadata fields are updated,
- no private key is read or persisted,
- updates performed by the reconciler use system actor semantics where audit metadata requires an actor.

Traefik itself continues to renew certificates. RP observes the renewed certificate and updates `certificateExpiresAt` and `certificateStatus=Active` accordingly.

This fulfills Stage 9 renewal responsibility without duplicating Traefik's ACME machinery.

## Routing reconciliation and cleanup

Current routing is primarily materialized during AppGroup deployment. Stage 9 will add a narrow ingress reconciliation path for route removal after desired routing changes.

### Events that require cleanup/reconciliation

- Domain detached from an `HttpEndpoint`,
- `HttpEndpoint` deleted,
- a Domain is deleted after successful detach,
- protocol mode changes in a way that removes an HTTP or HTTPS router.

### Behavior

The mutation remains responsible for updating desired state and AppGroup draft revision as today.

After the desired change is committed, Resource Portal schedules or invokes a focused ingress reconciliation action that removes obsolete Traefik routing for the affected AppGroup without pretending a full application rollout occurred.

The reconciliation must be idempotent and constrained to the deterministic RP stack/service/router namespace so it cannot remove unrelated Traefik configuration.

If the runtime is unavailable, desired state remains correct and the failure is surfaced/recorded. A later retry/reconciliation can complete runtime cleanup. The resource database mutation must not be rolled back solely because an already-obsolete route could not immediately be removed from a temporarily unavailable runtime.

This is intentionally a Stage 9-specific reconciliation path, not the generic Stage 16 Operation framework.

## Data model

Prefer reusing the current Domain/HttpEndpoint schema. Add a migration only when needed for missing observed metadata required by the implementation.

No certificate private-key columns will be added.

Existing Domain fields are expected to remain canonical for:

- `dnsStatus`,
- TLS enabled/required representation,
- `certificateStatus`,
- `certificateExpiresAt`.

If additional observation timestamps/error metadata are required for reliable API behavior, they may be added using the same pattern as Registry validation metadata, but only when implementation proves they are necessary.

## API behavior

Existing tenant-scoped Domain and HttpEndpoint API shapes should remain backward compatible.

Key behavior changes:

- protocol changes normalize TLS requirement consistently,
- Domain responses expose reconciled certificate metadata,
- attach/detach/delete operations trigger ingress reconciliation,
- existing `DomainInUse` and `CustomRootDomainInUse` protection remain unchanged,
- cross-tenant assignments remain rejected.

No endpoint will return certificate private keys or ACME account secrets.

## Configuration

Expected new/clarified environment configuration:

- `TRAEFIK_CERT_RESOLVER` — resolver name written to TLS router labels,
- certificate reconciliation interval,
- any Traefik observation endpoint/context required by the selected safe metadata adapter.

All new environment variables must be represented in `.env.example` and validated by the existing environment validation layer.

Production defaults must not silently configure a fake ACME resolver.

## Error handling

Use the existing Resource Portal API error envelope and logging conventions.

Important rules:

- malformed protocol/TLS configuration is rejected before deployment,
- reconciliation failures do not leak secrets,
- Traefik observation failures set safe error/status metadata and are logged with request/correlation context where available,
- route cleanup failures must distinguish desired-state success from runtime reconciliation failure,
- unrelated routers/services must never be deleted by cleanup logic.

## Audit

Existing user actions such as Domain create/update/assign/detach/delete continue to emit tenant Audit Log entries.

System-driven certificate metadata refresh should not produce noisy user-action audit entries for every successful polling cycle. Material state transitions (for example certificate entering `Error` or returning to `Active`) may be audited if this matches the existing system-event convention; otherwise structured worker logs are sufficient for Stage 9.

No ACME secrets, private keys, or certificate private material may appear in audit payloads.

## Testing

### Unit/regression tests

Add or extend tests for:

1. all four protocol modes,
2. TLS requirement derivation,
3. certresolver labels only on TLS routers,
4. HTTP-only router never receiving certresolver,
5. redirect mode preserving permanent HTTP→HTTPS redirect plus TLS resolver,
6. certificate observation mapping: Pending/Issuing/Active/Error,
7. expiry refresh after observed renewal,
8. observation failure isolation between Domains,
9. Domain detach and HttpEndpoint delete invoking idempotent route cleanup,
10. cleanup namespace safety,
11. tenant isolation and DomainInUse regressions.

### Integration verification

Extend the real Docker Swarm smoke flow where practical to prove:

- generated stack labels contain expected Traefik routing/TLS configuration,
- TLS modes render `certresolver`,
- route removal/reconciliation removes obsolete RP-owned routing without affecting unrelated stack resources.

CI must not depend on public Let's Encrypt issuance for every PR. Real public ACME issuance is environment-dependent and is therefore not a mandatory PR test unless a dedicated controlled integration environment is available.

The Stage 9 Definition of Done must distinguish configuration/runtime-path verification from a real public CA issuance test.

## Definition of Done

Stage 9 is complete when:

- steps 9.1–9.23 remain regression-safe,
- 9.24 TLS semantics are consistently enforced from protocol mode,
- 9.25 TLS routers request certificates through the configured Traefik ACME resolver,
- 9.26 certificate status is meaningful and reconciled,
- 9.27 expiry reflects observed certificate metadata,
- 9.28 renewal is automatic in Traefik and renewed metadata is reconciled into RP,
- 9.29 obsolete RP-owned ingress routing is actively reconciled after desired routing removal,
- relevant tests pass,
- CI and real Swarm integration are green,
- Wiki is updated from the verified merged implementation.
